# File Organizer

Directory-level organizer and the PRD's second acceptance app (`docs/loom-mvp-prd.md` §20). Pick a directory, pick a rule — by extension or by date (`YYYY-MM`) — and preview a dry-run plan listing every top-level file mapped to its target category folder. Execute moves the planned files; conflicts (destination exists) are skipped and never overwritten, cross-volume moves are refused, and directories and symlinks are never touched. Drive roots are rejected so one mis-click cannot mass-move a volume. Rules (mode, fallback category) and the last directory persist in app-scoped storage.

Run from the repository root: `npm run mini -- build file-organizer`, `npm run mini -- validate file-organizer`, then `npm run mini -- run file-organizer`. With Dry Run checked, Execute only refreshes the preview. CLI: `mini invoke file-organizer preview` scans the stored directory and returns counts; `mini invoke file-organizer execute` applies the current plan (requires a preview in the same session).

Pure planning logic lives in `src/rules.ts` and is covered by `tests/file-organizer.test.cjs` (classification, conflict detection, symlink/directory filtering, and a real-fs move run in a temp directory). File contents are not logged; logs carry counts only. Use a disposable test directory: the Host `files.move` refuses existing destinations and moves cross-volume via a verified copy chain, but still cannot guarantee atomicity against external races on the same paths. A disabled app must be enabled through the management center or `mini enable file-organizer` before running it.
