## 额外的一些验收体验

- 关于mini app的关闭,当前的内存是会越用越大的,没有清理机制导致越来越大,需要多种清理机制:如长时间未唤起自动清理,可配置时间;对于mini app的关闭事件,可以额外注册一个"自动停止",避免不必要的隐式常驻的发生;其他你可以再评估。
  → **已实现「闲置自动停止」(2026-09-28)**:App 在 `app.yaml` 里声明即可开启,缺省关闭、不影响现有 App:
  ```yaml
  lifecycle:
    idleStopMinutes: 30   # 运行中超过 30 分钟无 invoke 且无窗口 show/focus 即自动停止
  ```
  语义:只对**运行中**的 App 生效;任何一次 invoke、启动、窗口显示/获得焦点都会重置计时;到时走**正常 stop**(热键/窗口/helper 全部清理,可再次启动),不是杀进程。上限 7 天。日志会记录"闲置超过 N 分钟,自动停止"。注意本项为纯代码实现 + 冒烟回归,尚未真机验证——建议挑一个 App(如 file-organizer)设 `idleStopMinutes: 1` 实测一次。
  其他清理手段(内存超限回收、Host 级全局闲置策略)暂不做:收益/复杂度比不高,先看这个够不够用。
