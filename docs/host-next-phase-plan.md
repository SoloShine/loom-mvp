## 实现前硬门槛：五项契约

以下先补契约测试并让它们在旧实现上暴露缺口，再进入 A/B/C；HTTP（控制面）统一 `{ok:false,code,error}`，IPC 使用带 `code` 的可序列化拒绝结果或可稳定解析的拒绝异常，CLI 将其映射为非零退出码。错误码为本阶段目标而非现状；只读操作不因展示 broken 数据而失败。权限声明仅是能力提示，以下 Electron 页面权限拒绝与 sender 校验是 Host 自身控制面边界，不等于对任意 App 建立强制沙箱。

1. **CSP、导航、权限请求与 sender 矩阵**（A 前置）。仅管理窗/Launcher 当前 `webContents` 且当前主框架确实加载各自的打包 `file://.../management/index.html` / `.../launcher/index.html` 可调用本窗口 channel；管理页只可调用 `mini:management:getApps/getApp/action/getHistory/getLogs/getSettings/patchSettings`，Launcher 只可调用 `mini:launcher:getApps/startApp/invoke/hide/manage`；跨窗口、App 窗口、伪 sender、已销毁或换页 sender 均 `FORBIDDEN`，on 型消息直接丢弃并记诊断，不可触发副作用。`mini:svc`/`mini:ui-to-app` 仅当前运行且归属正确的 App webContents；process handle、window id、hotkey owner 均按 `appId` 二次校验，App A 不得写/杀 App B helper 或控制其窗口/热键。页面只允许本地打包入口及其本地静态资源，不开放远程 URL；管理/Launcher 主框架 `will-navigate`、`setWindowOpenHandler` 拒绝非白名单导航与一切新窗口，禁止重定向绕过，加载失败显式报错；会话 permission request/check handler 默认拒绝两页不需要的请求（含媒体、地理位置、通知等），不借此拦截 App 自身有意使用的 Electron/OS API。逐页扫描实际构建 HTML：管理现有 CSP 与内联 CSS 要一致，Launcher 目前无 CSP（`host/dist/management/index.html:2-4`、`host/dist/launcher/index.html:1-28`），补与产物相符的严格策略并禁止 `unsafe-eval`、内联脚本；若迁走内联样式则移到静态 CSS，不靠宽泛 `unsafe-inline`。静态扫描不替代 Windows Electron 真机加载/交互。管理 IPC 已有 sender 检查，Launcher 尚无（`host/src/main/management.ts:14-35`、`host/src/main/launcher.ts:132-160`）；逐 channel 伪 sender、跨页面、导航/重定向、`window.open`、权限请求、CSP 违规与正常入口回归必须通过。
2. **退出协调器与历史落盘**（A 前置）。`before-quit` 首次同步 `preventDefault`，状态 `running → draining → finalizing → ready`，保存同一个 Promise；draining 起拒绝新 HTTP/IPC start/invoke/reload 和新 helper。第二次 quit 在 `draining/finalizing` 仍阻止默认退出并复用同一 Promise，不重入 stop；到 `ready` 才放行真实退出。逐 App 等待 stop 并收集 `{appId,runId,outcome,error}`，设置总时限 12 秒及单 App 剩余预算；到期停止等待原 stopAll 的后续副作用、强杀未退出的 runtime/helper 树并等待退出确认，再关闭窗口/热键/control 与 tray。不能对仍运行的 `stopAll` 做 `Promise.race` 后并行清理（现状 `host/src/main/index.ts:90-107`）。强杀确认后写唯一 `stop` 失败（timeout）或 `crash` 事件；无法确认终结或 history/active 落盘失败时保留 active run、记录可观察 `SHUTDOWN_INCOMPLETE`/故障日志，下一次启动以同 runId 稳定 eventId 恢复为唯一 `interrupted`，不得把未终结写成成功 stop。终结顺序：确认进程树结束 → 带稳定 eventId 的 history append+fsync → active 原子移除；任一步失败保持可重试标记，重启去重（当前 `host/src/main/history.ts:25-74` 先清 active、吞 append 失败）。注入 stop 卡死、kill 失败、append/rename 失败、二次 quit、并发 disable/start、重复重启，断言同 run 至多一个最终事件、active 文件、history 行/eventId、exit code 与无孤儿；Windows 真退出再验窗口/热键/helper 树释放。
3. **disabled/broken DTO 与动作**（B 前置，可在 A 的公共动作通道落地）。管理 IPC、HTTP `/apps`/详情和 Launcher 统一判别 DTO：broken `{id,name:id,path:dir,status:'broken',enabled:false,favorite:false,error,permissions:[],commands:[],hotkeys:[],manifestIssues:[]}`，可选元数据用 `null` 或明确缺席且 UI 做判别，不访问未定义 `.length`；正常 disabled 保留完整元数据和 `enabled:false`，不能 start/invoke/reload。未知 id=`NOT_FOUND`/HTTP 404；非法参数或动作=`INVALID_ARGUMENT`/400；broken 的 start/stop/reload/enable/disable/invoke/favorite/unfavorite 一律 `BROKEN_MANIFEST`/409；disabled 的 start/invoke/reload=`APP_DISABLED`/409；停止中或退出中=`APP_BUSY`/409；持久化失败=`PERSISTENCE_FAILED`/500；IPC 采用同 code，拒绝时状态不变。正常项 enable 只在修复清单并重扫为正常项后可用（broken 不能靠按钮恢复）；disable 等 stop 完成后才提交 enabled=false；favorite/unfavorite 对正常 disabled 允许，含幂等重复操作也必须返回实际目标 favorite 值。成功响应携带刷新后的 DTO，断言目标状态与磁盘一致，否则失败；Launcher 不可执行项可显示但不发送执行请求。现状 broken favorite 写 meta 却返回 true（`host/src/main/registry.ts:170-176`），HTTP 与管理 IPC 都忽略返回值（`host/src/main/controlChannel.ts:151-160`、`host/src/main/management.ts:46-56`）。对 HTTP/IPC/CLI 每个动作×正常/disabled/broken/unknown 做表驱动测试，含修复清单→重扫→enable 路径与假成功回归。
4. **设置单写者、即时日志和回滚**（B 前置）。管理 IPC 与 HTTP PATCH `/settings` 共用串行写队列、同一校验与提交路径，禁止并发 patch 的陈旧快照覆盖。先验证完整候选 settings、预注册新热键并保留旧键；持久化原子成功后切换内存日志配置和热键所有权并释放旧键；提交任一步失败则恢复旧 state（磁盘+内存）、旧日志配置和热键，若恢复失败暴露 `ROLLBACK_FAILED`/500 并标明当前值，不报成功。对 `maxLogBytesPerApp`/`logRetentionDays` 成功 PATCH，下一条 append 立即采用新轮转/保留值，不需重启（当前 `configureLogging` 仅在 boot 调用，`host/src/main/index.ts:32-34`、`host/src/main/logging.ts:8-11`）；实际触发轮转/过期删除而非只比对 getter。注入原子写、注册/释放热键、rotate/prune 错误；测试失败前后磁盘、内存、快捷键仍一致、失败可观察；并发两入口仅串行结果可见，最后成功写入值同时反映在三个面，真实抢占冲突仅 Windows GUI 验。
5. **PNG 二进制交付决策**（C 前置）。保持 SDK `files.write(path,data:string)` 仅 UTF-8 文本（`sdk/src/index.ts:187-195`），`screen.captureRegion` 返回 dataURL（`sdk/src/index.ts:197-203`）；`screenshot-notes` 由 App 自有受控 Node runtime/helper 解析限定 `data:image/png;base64,`、校验字节/尺寸上限和 PNG 签名、解码 Buffer 后只向用户选定目录写临时文件，fsync、无覆盖 rename 后发布；失败清理临时文件且保留已有目标，helper 停止时清理子进程。只把文件名、元数据交给 UI，不传原始截图入日志/history/storage，不用 `files.write` 保存 PNG，不新增 Host bytes/stream API。自动化逐像素读取导出 PNG、测试坏 dataURL、超限、取消、重名、目录越界/写失败/断电模拟；Windows 多 DPI/负坐标保存像素另验。没有 App helper 接线与独立测试前，不能承诺截图导出已可用。

## 第一优先级：修复已见缺陷

1. **运行恢复与真实终结一致**。`initRuns` 先清空 active 文件再追加 interrupted，且 `event` 吞掉写失败；历史尾部 512 KiB 去重与查询尾部 1 MiB 的偏移分页无法保证长期可查和失败后重试（`host/src/main/history.ts:25-58`、`host/src/main/history.ts:75-96`）。改成逐 run 稳定 eventId + 持久化恢复进度：追加成功并 fsync 后才能从 active 移除，启动可重复恢复、同一 run 只出现一个终结事件；history 采用轮转/归档及稳定游标，损坏尾行可诊断、查询 bounded，旧文件兼容读取。`manager.start` 先 fork 再 `history.begin`，登记失败时杀掉进程且保证事件监听/清理；`finish` 失败不能把内存 runId 清掉而制造下次误报；stop/crash/start-failure 只生成一次终结事件（`host/src/main/runtime/manager.ts:112-150`、`host/src/main/runtime/manager.ts:154-189`、`host/src/main/runtime/manager.ts:316-350`）。区分正常 stop、意外 crash、Host 突然退出后的 interrupted，故障注入写失败/重启/重复回放验收。不要声称仅靠 JSONL append 与 rename 已具备数据库事务性。
2. **启停与调用串行化**。当前 `setEnabledAndReconcile` 只串行 enable/disable，start/invoke 走 manager，禁用检查发生在 start 的开头；并发禁用与启动可穿插（`host/src/main/appManagement.ts:3-16`、`host/src/main/runtime/manager.ts:90-95`、`host/src/main/runtime/manager.ts:197-217`）。用 per-App 操作队列或明确的状态机串行 start/stop/reload/invoke/disable；禁用时拒绝新调用并等待清理，stop 超时后不假报 stopped，只有进程和 helper/window/hotkey 清理确定完成才提交 disabled。`stopAll` 逐项 await，一项失败会中断余项；退出的 `Promise.race` 超时后仍会并行运行 stopAll 与 killAllHelpers（`host/src/main/runtime/manager.ts:236-240`、`host/src/main/index.ts:90-106`）；改幂等、有界 shutdown，逐 App 收集错误并在退出前完成或明确强杀及状态落盘。
3. **控制面归属与 helper 所有权**。管理 IPC 校验 sender，但 Launcher handlers 不校验 sender（`host/src/main/management.ts:14-35`、`host/src/main/launcher.ts:132-160`）；App renderer 的 `mini:svc` 仅按 webContents 归属，不检查 App 仍启用/运行，分发也没有权限强制边界（`host/src/main/index.ts:45-68`、`host/src/main/services/dispatcher.ts:19-29`）。给 Launcher IPC 加窗口归属和 schema 校验；所有服务调用检查生命周期与 App 归属，尤其 `process.write/kill` 当前只认全局 handleId（`host/src/main/services/dispatcher.ts:125-133`、`host/src/main/services/processSvc.ts:56-76`），须按 ctx.appId 验证；仅声明权限仍明确是提示，不宣称沙箱或强制授权。`runtime.json` 写入无显式文件权限，CLI 在 ping 失败后可删除发现文件（`host/src/main/controlChannel.ts:183-207`、`cli/src/client.ts:84-103`）；收紧当前用户访问、校验 PID/端口/token 与真实进程，避免误删仍在启动的 Host 文件，控制服务启动失败必须使 boot 明确失败而非未处理异步异常（`host/src/main/index.ts:71-76`）。
4. **用户可见的管理契约**。Launcher 搜索仅按文本分数排序、未传 favorite/lastUsedAt/enable 状态；禁用项仍可选，失败则隐藏 palette（`host/src/main/launcher.ts:132-146`、`host/src/launcher/ui.ts:53-60`、`host/src/launcher/ui.ts:95-121`）；补收藏/最近使用排序（搜索相关度优先）、禁用/破损提示及重新启用入口。管理 UI `AppInfo.permissions` 必填，broken API 未给它，详情直接访问 `.length`；broken 的 enable/favorite 按钮可触发但后端拒绝或返回假成功（`host/src/management/ui.ts:1-9`、`host/src/main/management.ts:24-30`、`host/src/main/management.ts:46-55`、`host/src/main/registry.ts:170-175`）。统一 broken DTO（错误、路径、元数据、空权限/命令）与按钮策略；收藏失败不得返回成功；管理页切换 App/页签、远端状态变化需避免旧异步响应覆盖新选择，提供分页、筛选、下一页、截断提示。现在 UI 只显示首批 history/log（`host/src/management/ui.ts:10-14`）；control 和管理各复制一份尾读日志逻辑（`host/src/main/controlChannel.ts:118-130`、`host/src/main/management.ts:57-65`），抽同一只读服务。设置热键提交与更新实时生效要覆盖失败回滚；`configureLogging` 只在启动调用（`host/src/main/index.ts:32-35`、`host/src/main/management.ts:66-76`）。权限显示应识别完整已知枚举，而不是用 `screen|mouse|process` 前缀把 clipboard/storage 等误标未知（`host/src/management/ui.ts:8`、`host/src/main/manifest.ts:90-92`）。
5. **文件/日志兼容性缺口**。`files.move` 任意 rename 失败即 copy + 删除，目标已存在/复制中断可能导致覆盖或源丢失（`host/src/main/services/core.ts:29-42`）；默认不覆盖，只有跨卷错误才采用带确认的 copy-to-temp/校验/rename/源删除，失败保源；测试同卷、跨卷、目标冲突、权限拒绝。`storage.set` 先更新 cache 再写文件，写失败后内存与磁盘不一致（`host/src/main/services/core.ts:56-93`），先复制/验证/原子写再替换 cache，坏 JSON 不静默清零。日志轮转 `rotate`/`prune` 吞异常且每次 append 扫目录，没有总容量上限；CLI `logs` 初次读整个文件、follow 一次分配从 offset 到 EOF，轮转跨文件期间可漏行（`host/src/main/logging.ts:17-47`、`cli/src/index.ts:195-227`）；有限流读取、分块行边界、轮转身份与截断检查、可观测的失败计数和保留策略。以上由临时目录的自动化故障注入先建立回归测试。

## Host 基础能力补齐原则

继续用 Electron/Node 原生能力与现有 TS + esbuild + Node test runner，不额外引入前端框架或数据库；本阶段仅实现 bounded JSONL 查询/轮转，数据库切换不在交付内（`package.json:10-24`、`host/src/management/ui.ts:1-14`）。SDK 现有 files 是 UTF-8 文本和同步 FS 封装，clipboard 只支持 text，screen 返回 dataURL，notification 仅 show，窗口 create 仅 type/宽高，process 有 spawn/write/kill（`sdk/src/index.ts:181-203`、`sdk/src/index.ts:238-274`、`host/src/main/services/core.ts:17-52`、`host/src/main/services/windows.ts:98-117`）。三个 App 优先使用既有接口，截图 PNG 按上文 App 自有 Node helper 路径；不在此阶段新增 Host bytes/stream 或把业务规则塞进 Host。

- **文件和数据**：`files` 是显式选择的本地路径/UTF-8 文本；截图二进制仅由示例 App 的受控 Node helper 写入，不借文本 API 做 base64 文件。storage 保持每 App JSON namespace，不与 host-state 混合。`mini validate` 校验产物与清单，未知 permissions 警告，缺 Python/helper 时给可操作错误；清单仍只声明能力，不当作访问控制（`host/src/main/registry.ts:43-81`、`host/src/main/manifest.ts:90-108`、`docs/loom-mvp-prd.md:808-840`）。
- **桌面交互**：窗口保留 none/window/floating/overlay；新工具优先 none/window，使用 system picker/文本 clipboard/通知/manifest hotkey。通知不支持返回 false、被系统静音时不作为任务成功凭据（`host/src/main/services/core.ts:99-104`）。窗口关闭/隐藏/重载的语义与资源回收统一；对屏幕区域进行正数、边界、跨屏验证，修复当前按各显示器 `bounds * scaleFactor` 推物理原点的潜在混合 DPI/负坐标问题，明确跨显示器矩形要拆分还是拒绝（`host/src/main/services/screen.ts:18-35`、`host/src/main/services/screen.ts:71-95`、`docs/loom-mvp-prd.md:403-407`）。选区使用系统截图工具和 Python OpenCV，必须检测依赖/取消/超时，不能算无依赖能力（`host/src/main/services/screen.ts:115-120`、`host/src/main/services/screen.ts:207-245`）。
- **诊断和 CLI**：API 错误结构/非零退出码一致；分页历史/log 提供稳定游标、行数和响应字节上限；历史不记录参数、返回值、剪贴板、截图；UI 仅展示授权本地数据，日志可能含敏感输出（`docs/host-foundation-plan.md:35-37`、`docs/host-foundation-plan.md:47-55`）。`mini run` 不应吞掉因 disabled 或通讯错误导致的真实失败并当成“未注册”处理（`cli/src/index.ts:127-145`）。离线 `mini list/validate/logs` 与在线命令一致使用 `MINI_ROOT/MINI_DATA_DIR/MINI_APPS_DIR`（`cli/src/client.ts:4-14`、`host/src/main/config.ts:6-28`）；保留 `mini logs --follow` 与原文件路径（`docs/loom-mvp-prd.md:588-624`）。

## 明确非目标

不做 App 商店、账号/云同步、自动更新、内置 Agent、远程控制、多人协作、跨平台完整支持或商业分发（`docs/loom-mvp-prd.md:884-918`）；不做任意 App 的安全沙箱、基于 manifest 的权限审批/强制阻断承诺（`docs/loom-mvp-prd.md:751-755`、`docs/loom-mvp-prd.md:808-840`），但管理/Launcher 自身的 CSP、导航、IPC sender 与权限请求拒绝是本阶段必须兑现的 Host 边界；不做新的通用 Host bytes/stream API、用 `files.write` 写 PNG、自动移动真实 Downloads、后台剪贴板监听、OCR/大规模屏幕分析、通用图像处理框架、连连看规则迁入 Host、数据库迁移或物理删除 App 目录（`docs/host-foundation-plan.md:33-45`、`docs/loom-mvp-prd.md:1236-1242`）。
